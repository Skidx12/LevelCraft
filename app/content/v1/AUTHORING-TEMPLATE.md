# Mission Authoring Template — Schema Version 1

Copy an approved mission JSON file and replace every field deliberately. Do not delete a required section because a topic appears simple.

## Authoring order

1. Declare stable ID, legacy mapping, arc, rank, status and review metadata.
2. Write observable outcomes and prerequisite mission IDs.
3. Write the briefing from problem to vocabulary to readiness check.
4. Supply a complete demonstration with file paths, run instructions and output.
5. Write guided steps using Goal, Why, Where, Action, Observe, Failure and Checkpoint.
6. Add one controlled break-and-repair exercise.
7. Add Recall, Trace, Compare and Predict questions only after their concepts are taught.
8. Write Hunter Notes with use/non-use cases, trade-offs, mistakes and primary references.
9. Write the quest's current state, constraints, acceptance criteria, starter files and evidence rules.
10. Finish with the trial and debrief.

## Status workflow

`draft → technical_review → beginner_review → editorial_review → approved → published`

Only `approved` or `published` content may be offered as normal learner progression. Earlier statuses remain visible only in Content Review Mode.

## Review requirement

Complete `docs/curriculum/CONTENT-REVIEW-SCORECARD.md`. Publication requires no blocking failures, at least 85/100 overall and the required reviewers.
